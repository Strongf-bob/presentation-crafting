# Сборка деки: self-contained HTML

Этот референс делает скилл самодостаточным: его достаточно для сборки `deck.html` без внешних зависимостей. Если установлен скилл `design-system` — его токены, чарты и валидацию можно использовать поверх этого файла, но он **не требуется**.

## Формат файла

- Один файл `deck.html`, self-contained: весь CSS и JS инлайн внутри файла, картинки — относительными путями в `assets/`.
- Слайд 16:9, базовый размер 1280×720; каждый слайд занимает весь вьюпорт (`100vh`/`100dvh`), `overflow: hidden` — слайд никогда не скроллится внутри себя.
- Типографика через `clamp()` — размер шрифта масштабируется вместе с вьюпортом.
- Навигация: стрелки клавиатуры (←/→, Space), клик по краям слайда, прогресс-бар, счётчик «N / total».
- Шрифты — system font stack по умолчанию. Внешние шрифты (CDN) — только если зафиксированы в брифе (какие + дата обращения к источнику); при офлайн-сборке — никаких.
- Анимации минимальны и отключаются по `prefers-reduced-motion`.

Визуальные правила (типографика, цвет, сетка, лимиты типов слайдов, анти-слоп) — в `references/slide-design.md`.

## Токены (CSS variables)

В начале `<style>` объявить `:root` с токенами; значения — из брифа (стиль, тон, брендбук, если есть):

```css
:root {
  --slide-bg: ...;
  --text-primary: ...;
  --text-secondary: ...;
  --accent: ...;
  --font-heading: ...;
  --font-body: ...;
}
```

Весь CSS слайдов использует только `var(--...)` — никаких захардкоженных цветов и шрифтов внутри правил. Тогда смена стиля = правка токенов в одном месте.

## Типографика и плотность

- Заголовок слайда: 36–48pt, заголовок = вывод («Выручка выросла в 5 раз», не «Наша выручка»).
- Тело: 18–24pt, минимум 18pt — источник истины по числам типографики: `references/slide-design.md`. Если не влезает — текста слишком много: сократить текст, а не уменьшать шрифт.
- Плотность — по шкале из `references/audience-structures.md` (минимум / средняя / плотная), уровень — из брифа с учётом формата подачи (живое / чтение).
- Важное — сверху: слайд читают сверху вниз.
- Декор по минимуму: без лишних иконок, анимаций и переходов.

## Чарты

- Данные чарта = данные из спека, цифры совпадают дословно; источник и дата данных из спека выносятся подписью под чарт (мелкий шрифт).
- Если деку открывают онлайн — Chart.js через CDN, например `https://cdn.jsdelivr.net/npm/chart.js@4` (версия пинится, URL и дата обращения фиксируются в спеке).
- Если нужна работа офлайн — простые SVG-чарты инлайн вместо Chart.js. Выбор фиксировать в брифе.

## Изображения

- Только относительные пути `assets/...` — никаких внешних URL без проверки.
- Скриншоты интерфейсов — по минимуму (они шумные); вместо них — простые схемы.
- Сгенерированные изображения и диаграммы — тоже в `assets/`, kebab-case; происхождение указать в спеке.

## Валидация перед показом

Способы проверки — по убыванию качества, использовать верхний доступный; чем реально проверял — сказать пользователю, что не смог проверить — назвать явно:

1. Браузер: открыть `deck.html` и пройти все слайды от первого до последнего.
2. Скриншот-инструмент: снять каждый слайд и проверить визуально.
3. Нет ни того ни другого: статическая проверка разметки — высота блоков и контента на слайд, `overflow: hidden`, `clamp()` в типографике, полнота кода навигации, пути `assets/` существуют.
4. На каждом слайде: ничего не вылезает за границы, текст читаем, чарт рендерится.
5. Навигация работает: стрелки, клик, прогресс-бар, счётчик.
6. Цифры на чартах совпадают с цифрами в тексте слайда и в спеке — вплоть до знаков, вместе с датами.

## PPTX и PDF

Оба формата — только если согласованы в брифе; по умолчанию делается только HTML.

- **PPTX** — генерация через `python-pptx` строго по спеку (тот же текст дословно, те же `assets/`). PPTX заказывают ради редактируемости, поэтому верность тексту важнее красоты.
- **PDF** — печать `deck.html` в PDF из браузера или headless Chrome; каждый слайд — страница 16:9.
