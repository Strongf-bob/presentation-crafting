# Бриф: <Название презентации>

> Заполняется до начала работы. Без одобрения брифа пользователем слайды не создавать.
> Это источник истины: при любых сомнениях в процессе работы возвращаться сюда.

## 1. Цель

- Зачем эта презентация? (убедить, продать, защитить, отчитаться, обучить)
- Какое действие / решение должно последовать после неё?
- Формат подачи: живое выступление / чтение с экрана / демо-дек
  (влияет на плотность — см. «Параметры» в `references/audience-structures.md`)
- Регламент: сколько минут на выступление? (→ число слайдов: 1–2 мин/слайд)

## 2. Целевая аудитория

- Кто именно? (роль, уровень, знакомство с темой)
- Что для них важно?
- Какие возражения и вопросы ожидаются?

## 3. Стиль и подача

> Параметры этого раздела выводятся из таблицы ситуаций (`references/audience-structures.md`)
> по ЦА и формату подачи — не спрашивать у пользователя напрямую, а зафиксировать
> здесь и подтвердить при одобрении брифа.

- Стиль оформления:
- Есть ли брендбук / корпоративный шаблон, которому надо следовать?
- Что важнее: дизайн или текст? (по умолчанию — текст; исключения в таблице ситуаций)
- Плотность текста на слайд: минимум / средняя / плотная (из таблицы + поправка на формат подачи)
- Тон: формальный / нейтральный / дружелюбный

## 4. Структура

- Архетип: (информировать / убедить / защитить / обучить / отчитаться / вдохновить / гибрид)
- Выбранная структура: (из `references/audience-structures.md`)
- Обоснование: почему именно эта структура под эту ЦА
- Число слайдов: (выводится из регламента: минуты / 1,5 ±; appendix не считается)
- Обязательные блоки / слайды (если есть требования):

## 5. Материалы

- Что обязательно попадает на слайды (данные, цифры, картинки, документы)
- Вложения: список файлов для `assets/`
- Источники ключевых цифр (откуда взяты: файл, документ, данные пользователя)
- Чего НЕТ — что придётся додумать или сгенерировать

## 6. Допущения

- Что взято по умолчанию (если пользователь не ответил): стиль, плотность, формат вывода
