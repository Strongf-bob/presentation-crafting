# Presentation Crafting

Скилл для создания презентаций под конкретную целевую аудиторию: от ресерча и брифа до готовой деки, с выбором структуры по ЦА (YC Seed, YC Series A, «9 блоков», продажи, внутренние и т.д.) и защитой от выдуманных фактов и AI-slop дизайна.

## Что делает скилл

Перед созданием презентации скилл:

1. **Собирает базу** — задаёт обязательные вопросы (цель, ЦА, регламент, материалы, формат); стиль и плотность выводит сам по таблице ситуаций. Не начинает работу, пока база не собрана и бриф не одобрен.
2. **Проводит ресерч** — читает вложения, исследует кодовую базу (для презентаций о проекте — только правда о том, как она работает: никаких выдуманных фич и цифр), при необходимости ходит в веб. На слайды попадают только подтверждённые факты.
3. **Создаёт папку** — `presentations/<deck-name>/`, всю работу ведёт внутри неё.
4. **Пишет бриф** — `01-brief.md`: зачем презентация, ЦА, регламент, стиль, какая структура выбрана и почему.
5. **Пишет спек слайдов** — `02-deck-spec.md`: структура, потом каждый слайд с типом, точным текстом, источниками цифр, картинками из `assets/` и заметками докладчика.
6. **Собирает ассеты** — `assets/` с вложениями, которые попадают на слайды.
7. **Делает презентацию** — по умолчанию self-contained HTML по встроенным референсам (внешние скиллы не требуются); PPTX/PDF — по договорённости. Дизайн — по анти-слоп правилам: типы слайдов с лимитами, ≤2 шрифтов, ≤3 цветов, контраст WCAG.
8. **Проверяет** — чек-лист верификации (включая ghost deck test: заголовки подряд должны рассказывать всю историю) + обязательный фактчекинг в два захода.

Для малых внутренних дек (≤5 слайдов) — lite-режим: сжатый бриф в начале спека, без отдельного раунда одобрения.

## Структура репозитория

```
presentation-crafting/
├── SKILL.md                        # сам скилл: воркфлоу, preflight, lite-режим, чек-листы
├── references/
│   ├── audience-structures.md      # ЦА → структура: архетипы, плотность, регламент, YC, 9 блоков,
│   │                               #   академические правила (ghost deck test, цитирование)
│   ├── research.md                 # ресерч фактуры: кодовая база, вложения, веб; grounding
│   ├── slide-design.md             # визуальные правила: типы слайдов, лимиты, анти-слоп
│   └── html-deck.md                # сборка деки: HTML, токены, навигация, чарты, PPTX/PDF
├── templates/
│   ├── brief.md                    # шаблон брифа
│   └── deck-spec.md                # шаблон спека слайдов
└── examples/
    ├── brief-example.md            # пример заполненного брифа
    └── deck-spec-example.md        # пример заполненного спека (3 слайда)
```

## Установка

Скопировать или симлинкнуть в каталог скиллов:

```bash
ln -s "$PWD/presentation-crafting" ~/.codex/skills/presentation-crafting
```

## Использование

Просто попросить сделать презентацию:

> Сделай питч-дек для инвесторов по нашему проекту

Скилл сам задаст вопросы для брифа, исследует материалы и кодовую базу, создаст папку и пройдёт весь воркфлоу.

## Источники и благодарности

Скилл — сборная солянка проверенных подходов. Из этих репозиториев заимствованы идеи (все под MIT):

- **[ICIP-CAS/PPTAgent](https://github.com/ICIP-CAS/PPTAgent)** (EMNLP 2025) — идея фазы ресерча перед генерацией: сначала анализ материалов, потом слайды; оценка деки по осям контент/дизайн/связность.
- **[Gabberflast/academic-pptx-skill](https://github.com/Gabberflast/academic-pptx-skill)** — академические правила качества: action titles, ghost deck test, один exhibit на слайд с аннотацией, цитирование на слайде + слайд References, финал на Conclusions (не «Thank you»), регламент ≤1 слайда/мин.
- **[proyecto26/slides-ai-plugin](https://github.com/proyecto26/slides-ai-plugin)** — анти-слоп дизайн-правила (font soup, color rainbow, wall of text, AI slop aesthetics), словарь типов слайдов с лимитами плотности, структура от длительности выступления, viewport-fitting для HTML (`100vh`, `overflow: hidden`, `clamp()`).

Плюс собственные наработки: 6 архетипов по ЦА, структура «9 блоков» с картой возражений, YC-структуры (Seed / Series A), двухзаходный фактчекинг, lite-режим для малых дек.
